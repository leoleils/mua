# 下棋通知修复说明

## 🐛 问题描述

用户反馈：下棋通知应该包含另外一个玩家下在了什么地方的信息，需要在棋盘上显示。

从日志观察到的现象：
```
2025-07-16 15:48:01,541 - tcp_client - INFO - 💬 收到简单通知: 状态=1, 消息='下棋成功'
2025-07-16 15:48:01,541 - message_handler - INFO - ♟️ 处理下棋成功通知: 下棋成功
```

**问题分析**：
1. 下棋通知被错误地解析为"简单通知"，而不是包含详细信息的 `PiecePlacedNotification`
2. 缺少下棋位置、玩家信息、棋子颜色等关键信息
3. 界面无法正确更新棋盘状态

## 🔍 根本原因

### 消息处理流程问题

根据API文档，`PiecePlacedNotification` 应该：
- 通过 `CLIENT_MESSAGE` 类型发送
- 消息头的 `request_id` 为 `"PiecePlacedNotification"`
- payload 为 `PlacePieceResponse` 格式，包含完整游戏状态

**问题所在**：
- `tcp_client.py` 在处理 `CLIENT_MESSAGE` 时没有检查消息头的 `request_id`
- 而是通过尝试不同的 protobuf 格式来猜测消息类型
- 导致 `PlacePieceResponse` 没有被正确解析

## 🛠️ 修复方案

### 1. 修复 TCP 客户端消息解析

**文件**: `client/tcp_client.py`

**修改内容**：
- 在处理 `CLIENT_MESSAGE` 时，首先检查 `request_id` 字段
- 根据通知类型进行专门处理：
  - `PiecePlacedNotification` → 解析为 `PlacePieceResponse`
  - `GameStartNotification` → 解析为 `GameStateNotify`
  - `PlayerJoinedNotification` 等 → 解析为 `PlayerEventNotify`

**关键代码**：
```python
# 根据通知类型进行具体处理
if notification_type == "PiecePlacedNotification":
    try:
        from gomoku_pb2 import PlacePieceResponse
        piece_response = PlacePieceResponse()
        piece_response.ParseFromString(game_message.payload)
        
        # 提取下棋位置信息
        if piece_response.game_state and piece_response.game_state.move_history:
            last_move = piece_response.game_state.move_history[-1]
            self.logger.info(f"📍 最新下棋位置: 玩家={last_move.player_id}, 位置=({last_move.x}, {last_move.y}), 颜色={last_move.color}")
        
        if hasattr(self.message_handler, 'handle_piece_placed_notification'):
            self.message_handler.handle_piece_placed_notification(piece_response)
```

### 2. 增强消息处理器

**文件**: `client/message_handler.py`

**新增方法**: `handle_piece_placed_notification()`

**功能特性**：
- 解析 `PlacePieceResponse` 格式的下棋通知
- 提取详细的下棋信息（位置、玩家、颜色、步数等）
- 构造包含完整信息的 `move_info` 字典
- 支持多种处理器回调

**关键信息提取**：
```python
move_info = {
    'success': piece_response.success,
    'message': piece_response.message,
    'player_id': last_move.player_id,
    'x': last_move.x,
    'y': last_move.y,
    'color': last_move.color,
    'move_number': last_move.move_number,
    'current_turn': piece_response.game_state.current_turn,
    'total_moves': piece_response.game_state.total_moves,
    'game_result': piece_response.game_state.result,
    'board': list(piece_response.game_state.board),
    'game_state': piece_response.game_state
}
```

### 3. 更新 GUI 处理

**文件**: `client/gomoku_gui.py`

**修改内容**：
- 注册新的处理器：`piece_placed_notification`
- 更新 `_handle_piece_placed_notification()` 方法支持新的 `move_info` 字典格式
- 保持向后兼容性，同时支持旧格式

**显示信息增强**：
```python
self.log_message(f"📍 落子位置: ({x}, {y})")
self.log_message(f"🎮 玩家: {player_id}")
self.log_message(f"🔢 第 {move_number} 步 (总步数: {total_moves})")
self.log_message(f"{color_emoji} 棋子颜色: {color_name}")

```

## 📝 API 协议确认

根据 API 文档，下棋通知的完整协议格式：

**gRPC 推送格式**：
```protobuf
{
  "player_id": "target_player_123",
  "cb_type": "PUSH",
  "message": {
    "msg_head": {
      "player_id": "target_player_123",
      "service_name": "gomokusvr",
      "request_id": "PiecePlacedNotification",
      "timestamp": 1699123456789
    },
    "msg_type": "CLIENT_MESSAGE",
    "payload": <PlacePieceResponse序列化后的bytes>
  }
}
```

**Payload 内容** (`PlacePieceResponse`):
```protobuf
{
  "success": true,
  "message": "下棋成功",
  "game_state": {
    "board": [0, 0, 0, ..., 1, 0, ...],
    "current_turn": "WHITE",
    "result": "ONGOING",
    "total_moves": 3,
    "move_history": [
      {
        "player_id": "player_123",
        "color": "BLACK",
        "x": 7,
        "y": 7,
        "move_number": 1
      }
    ]
  }
}
```
