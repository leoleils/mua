# 坐标映射修复说明

## 🐛 问题描述

用户反馈：GUI目前有问题，鼠标点击屏幕位置坐标和实际下棋的坐标不一致。

## 🔍 问题分析

### 原始问题流程

1. **用户点击棋盘** → 
2. **GUI获取鼠标坐标** → 
3. **转换为棋盘坐标** → 
4. **发送给后端API** → 
5. **后端下棋** → 
6. **通知其他玩家** → 
7. **GUI显示棋子** ❌ **位置不匹配**

### 根本原因分析

通过深入分析后端代码和前端代码，发现了坐标系统的映射问题：

#### 后端坐标系统（`minigame/gomokusvr/internal/game/game.go`）

```go
// 二维棋盘结构
Board [BoardSize][BoardSize]int32  // Board[x][y]

// 下棋操作
func (g *Game) PlacePiece(playerID string, x, y int32) error {
    g.Board[x][y] = pieceColor  // 使用Board[x][y]
}

// 转换为一维数组传输
for i := 0; i < BoardSize; i++ {      // i = x
    for j := 0; j < BoardSize; j++ {  // j = y
        board[i*BoardSize+j] = g.Board[i][j]  // 索引 = x * 15 + y
    }
}
```

#### 前端坐标系统（`client/gomoku_gui.py`）

```python
# 鼠标点击处理
def on_board_click(self, event):
    col = round((event.x - offset) / self.cell_size)  # 鼠标x → col（列）
    row = round((event.y - offset) / self.cell_size)  # 鼠标y → row（行）
    self.place_piece(row, col)

# 棋盘显示处理
def draw_pieces(self):
    for i, piece in enumerate(self.game_state.board):
        row = i // self.board_size    # row = i // 15
        col = i % self.board_size     # col = i % 15
        # 一维索引 i = row * 15 + col
```

#### 坐标映射关系

通过对比分析：

- **后端**: `board[i*BoardSize+j] = g.Board[i][j]` → 一维索引 = x * 15 + y
- **前端**: `i = row * 15 + col` → 一维索引 = row * 15 + col

因此坐标映射关系为：
- **后端的x** ↔ **前端的row**（垂直方向）
- **后端的y** ↔ **前端的col**（水平方向）

### 问题所在

**原来的错误实现**（已修复）：
```python
# 错误：GUI传递的参数顺序有误
def place_piece(self, row: int, col: int):
    # 错误地传递了(col, row)，导致坐标轴颠倒
    request_id = self.message_handler.place_piece(self.current_room_id, col, row)
```

## 🛠️ 修复方案

### 1. 修复GUI坐标传递

**文件**: `client/gomoku_gui.py`

**修复内容**：
```python
def place_piece(self, row: int, col: int):
    """下棋
    
    Args:
        row: 行坐标（垂直方向，对应API的x参数）
        col: 列坐标（水平方向，对应API的y参数）
    """
    # 修复坐标映射：API期望(x, y)，其中x=行，y=列（根据后端Board[x][y]结构）
    request_id = self.message_handler.place_piece(self.current_room_id, row, col)
    self.log_message(f"📤 下棋请求: 界面位置({row}, {col}) -> API坐标(x={row}, y={col})")
```

**关键修复点**：
- 传递给API的参数顺序：`(row, col)` 对应 `(x, y)`
- 确保坐标映射一致性：界面行列对应后端x、y

### 2. 修复下棋通知显示

**文件**: `client/gomoku_gui.py`

**修复内容**：
```python
def _handle_piece_placed_notification(self, move_info):
    # 坐标说明
    x = move_info.get('x', -1)  # 后端x对应界面row
    y = move_info.get('y', -1)  # 后端y对应界面col
    
    # 修复显示逻辑
    if x >= 0 and y >= 0 and hasattr(self, 'board_canvas'):
        # 注意坐标映射：API的(x,y)对应界面的(row,col)
        self.log_message(f"🎯 单个位置更新: API坐标({x}, {y}) -> 界面位置(row={x}, col={y})")
        # 由于使用Canvas绘制，直接重绘整个棋盘
        self.draw_board()
```

## 📝 技术细节

### 坐标系统约定

**后端坐标系统** (`Board[x][y]`)：
- `x`: 行索引（0-14），垂直方向
- `y`: 列索引（0-14），水平方向
- 一维索引：`index = x * 15 + y`

**前端界面坐标**：
- `row`: 界面行（0-14），对应后端x
- `col`: 界面列（0-14），对应后端y
- 鼠标坐标：`event.x` → `col`, `event.y` → `row`

### API协议确认

```protobuf
message PlacePieceRequest {
  string room_id = 1;
  int32 x = 2;          // X坐标（0-14）对应界面row
  int32 y = 3;          // Y坐标（0-14）对应界面col
}
```
