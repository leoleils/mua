# 编码错误修复说明

## 问题描述

用户在使用五子棋客户端时遇到UTF-8编码错误：

```
2025-07-16 11:31:38,939 - tcp_client - ERROR - ❌ 消息处理失败: 'utf-8' codec can't decode byte 0xe6 in position 11: invalid continuation byte
2025-07-16 11:31:51,867 - tcp_client - ERROR - ❌ 消息处理失败: 'utf-8' codec can't decode byte 0x86 in position 17: invalid start byte
```

以及系统消息处理错误：
```
INFO:message_handler:⚙️ 收到系统消息: 
d92d1771
        player_9878JOIN
ERROR:tcp_client:❌ 消息处理失败: 'utf-8' codec can't decode bytes in position 63-64: invalid continuation byte
```

## 问题原因

1. **直接UTF-8解码**: 代码中多处直接使用 `payload.decode('utf-8')` 而没有错误处理
2. **混合数据处理**: 服务器发送的消息可能包含二进制protobuf数据和文本数据的混合
3. **编码错误传播**: 一旦发生编码错误，整个消息处理流程会崩溃

## 修复方案

### 1. tcp_client.py 修复

#### CLIENT_MESSAGE 处理 (第208行)
**修复前:**
```python
message = game_message.payload.decode('utf-8')
```

**修复后:**
```python
# 安全地解码系统消息，处理可能的编码错误
message = ""
try:
    message = game_message.payload.decode('utf-8')
except UnicodeDecodeError as e:
    self.logger.warning(f"⚠️ 客户端消息包含非UTF-8数据，使用错误处理: {e}")
    message = game_message.payload.decode('utf-8', errors='replace')
except Exception as e:
    self.logger.error(f"❌ 解码客户端消息失败: {e}")
    message = str(game_message.payload)
```

#### 系统消息处理增强
- 添加安全的UTF-8解码
- 增强错误诊断和日志记录
- 提供详细的调试信息

### 2. message_handler.py 修复

#### 推送通知载荷处理
**修复前:**
```python
try:
    text = payload.decode('utf-8')
    handler(text)
except:
    handler(payload)
```

**修复后:**
```python
try:
    # 首先尝试UTF-8解码
    text = payload.decode('utf-8')
    handler(text)
except UnicodeDecodeError as e:
    self.logger.warning(f"⚠️ 通知载荷包含非UTF-8数据 {method}: {e}")
    # 使用错误处理模式解码
    try:
        text = payload.decode('utf-8', errors='replace')
        handler(text)
    except Exception:
        # 如果仍然失败，传递原始数据
        handler(payload)
except Exception as e:
    self.logger.debug(f"📦 通知载荷不是文本格式 {method}: {e}")
    # 如果不是文本，直接传递原始数据
    handler(payload)
```

## 修复效果

### ✅ 编码错误处理
- **损坏的UTF-8序列**: 使用 `errors='replace'` 模式处理，将无效字符替换为 `�`
- **混合二进制数据**: 正确识别并处理protobuf格式的数据
- **中文字符消息**: 正常处理包含中文和表情符号的消息

### ✅ 错误诊断增强
- **详细错误信息**: 提供消息类型、服务名、请求ID、载荷大小等诊断信息
- **十六进制调试**: 对于编码错误，显示载荷的十六进制内容便于调试
- **分层错误处理**: 不同层级的错误有不同的处理策略

### ✅ 系统稳定性
- **无崩溃处理**: 编码错误不再导致程序崩溃
- **优雅降级**: 无法解码的数据会降级到原始字节处理
- **完整日志**: 所有处理过程都有完整的日志记录
