# 消息同步功能说明

## 功能概述

五子棋服务(`gomokusvr`)实现了完整的消息同步功能，当一个玩家执行游戏操作时，会通过**protobuf协议**将消息同步推送给房间内的其他玩家。

## 技术架构

### 通信协议
- **协议类型**: gRPC + Protocol Buffers
- **推送接口**: `gatesvr.GateSvr/PushToClient`
- **消息类型**: `CLIENT_MESSAGE` (客户端消息)
- **回调类型**: `PUSH` (异步推送，不等待回包)

### 消息流程
```
玩家操作 → gomokusvr业务逻辑 → 构造protobuf消息 → gRPC调用gatesvr → 推送到目标客户端
```

### 核心组件

#### 1. GateClient (内部客户端包)
- 文件位置: `internal/gateclient/gateclient.go`
- 功能: 封装与gatesvr的gRPC通信
- 主要类型:
  - `PushRequest`: 推送请求结构
  - `GameMessage`: 游戏消息结构
  - `GateSvrClient`: 客户端接口

#### 2. NotificationManager (通知管理器)
- 文件位置: `internal/notification/notification.go`
- 功能: 管理消息推送队列和gRPC连接池
- 特性:
  - 异步推送队列 (1000消息缓冲)
  - 3个工作协程并发处理
  - 自动连接管理和重连
  - 支持protobuf和JSON消息

## 支持的消息类型

### 1. 棋子放置通知 (PiecePlacedNotification)
**触发时机**: 玩家成功下棋后

**protobuf消息**: `pb.PlacePieceResponse`
```protobuf
message PlacePieceResponse {
  int32 result = 1;           // 操作结果
  string message = 2;         // 响应消息  
  GameState game_state = 3;   // 游戏状态
  bool is_win = 4;           // 是否获胜
  string winner_id = 5;      // 胜利者ID
}
```

**通知对象**: 房间内除当前玩家外的所有其他玩家

### 2. 游戏状态变化通知 (GameStateChangedNotification)
**触发时机**: 游戏状态发生变化时

**protobuf消息**: `pb.GameStateNotify`
```protobuf
message GameStateNotify {
  GameState game_state = 1;    // 当前游戏状态
  string event_type = 2;       // 事件类型
  string event_message = 3;    // 事件消息
}
```

### 3. 玩家加入房间通知 (PlayerJoinedNotification)
**触发时机**: 新玩家加入房间时

**protobuf消息**: `pb.PlayerEventNotify`
```protobuf
message PlayerEventNotify {
  string room_id = 1;     // 房间ID
  string player_id = 2;   // 玩家ID
  string event_type = 3;  // 事件类型: "JOIN"
}
```

**通知对象**: 房间内除新加入玩家外的所有其他玩家

### 4. 玩家离开房间通知 (PlayerLeftNotification)
**触发时机**: 玩家离开房间时

**protobuf消息**: `pb.PlayerEventNotify`
```protobuf
message PlayerEventNotify {
  string room_id = 1;     // 房间ID
  string player_id = 2;   // 玩家ID
  string event_type = 3;  // 事件类型: "LEAVE"
}
```

**通知对象**: 房间内除离开玩家外的所有其他玩家

## 消息格式详解

### gRPC消息结构
推送到gatesvr的完整消息格式：

```protobuf
message PushRequest {
  string player_id = 1;           // 目标玩家ID
  string ip = 2;                  // 客户端IP (可选)
  CallbackType cb_type = 3;       // 回调类型: PUSH
  GameMessage message = 4;        // 游戏消息内容
}

message GameMessage {
  HeadMessage msg_head = 1;       // 消息头
  MessageType msg_type = 2;       // 消息类型: CLIENT_MESSAGE
  bytes payload = 3;              // 消息载荷 (序列化的protobuf)
  int64 timestamp = 4;            // 时间戳
}

message HeadMessage {
  string player_id = 2;           // 玩家ID
  string service_name = 3;        // 服务名: "gomokusvr"
  string method = 4;              // 方法名 (如: "PiecePlacedNotification")
  int64 timestamp = 12;           // 时间戳
}
```

### 序列化流程
1. 将业务protobuf消息 (如`PlacePieceResponse`) 序列化为`bytes`
2. 构造`GameMessage`，将序列化结果放入`payload`字段
3. 构造`PushRequest`，设置目标玩家和回调类型
4. 通过gRPC调用`gatesvr.GateSvr/PushToClient`

## 使用示例

### 1. 通知其他玩家下棋
```go
// 在handler.go中处理下棋逻辑后
if resp.Result == 0 { // 下棋成功
    // 获取房间内其他玩家
    otherPlayers := room.GetOtherPlayers(req.Head.PlayerId)
    
    // 通知其他玩家
    notification.NotifyPiecePlaced(otherPlayers, resp)
}
```

### 2. 通知玩家加入房间
```go
// 在joinRoom逻辑中
if joinResult.Success {
    // 通知房间内其他玩家
    otherPlayers := room.GetOtherPlayers(playerID)
    notification.NotifyPlayerJoined(otherPlayers, roomID, playerID)
}
```

### 3. 自定义protobuf消息推送
```go
// 推送自定义protobuf消息
customMsg := &pb.CustomGameNotify{
    Type: "CUSTOM_EVENT",
    Data: "some data",
}

notification.PushGameNotification(playerID, customMsg, "CustomEventNotification")
```

## 性能特性

### 推送性能
- **延迟**: < 100ms (本地网络)
- **并发**: 支持3个工作协程并发推送
- **缓冲**: 1000消息队列缓冲，防止阻塞
- **重试**: 自动连接管理，失败时自动重建连接

### 内存使用
- **连接池**: 按gatesvr地址缓存gRPC连接
- **消息队列**: 约2-3MB内存占用 (1000消息 × 平均3KB)
- **序列化**: 高效的protobuf二进制序列化

### 错误处理
- **队列满**: 自动丢弃新消息，记录警告日志
- **网络异常**: 自动重建gRPC连接
- **超时控制**: 3秒推送超时，避免阻塞
- **日志记录**: 完整的成功/失败日志追踪

## 客户端接收示例

当客户端(如前端、移动端)连接到gatesvr后，会收到推送的protobuf消息。客户端需要：

1. **解析消息头**: 从`GameMessage.msg_head.method`获取消息类型
2. **反序列化载荷**: 将`GameMessage.payload`按对应的protobuf类型反序列化
3. **处理业务逻辑**: 根据消息类型更新UI或游戏状态

### JavaScript客户端示例
```javascript
// 假设收到WebSocket推送消息
websocket.onmessage = function(event) {
    const gameMessage = parseGameMessage(event.data);
    
    switch(gameMessage.msg_head.method) {
        case "PiecePlacedNotification":
            const placeResp = PlacePieceResponse.decode(gameMessage.payload);
            updateBoard(placeResp.game_state);
            break;
            
        case "PlayerJoinedNotification":
            const joinEvent = PlayerEventNotify.decode(gameMessage.payload);
            showPlayerJoined(joinEvent.player_id);
            break;
    }
};
```

## 部署说明

### 环境要求
- Go 1.19+
- gatesvr服务运行并注册到Nacos
- Nacos服务发现可用

### 启动服务
```bash
# 编译
go build -o gomokusvr cmd/main.go

# 运行
./gomokusvr -config config.yaml
```

### 验证推送功能
1. 启动gatesvr和gomokusvr
2. 客户端连接gatesvr并加入游戏房间
3. 进行下棋操作，观察其他玩家是否收到实时推送
4. 检查日志中的推送成功/失败记录

## 故障排查

### 常见问题
1. **推送失败**: 检查gatesvr连接状态和Nacos服务发现
2. **消息丢失**: 检查推送队列是否满，增大缓冲区
3. **延迟过高**: 检查网络状况和gRPC连接池状态
4. **内存泄漏**: 检查连接池是否正常清理
